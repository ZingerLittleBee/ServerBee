ServerBee 提供原生 iOS 配套应用，把服务器监控带到你的手机：实时指标、告警历史，以及随时随地管理服务器。目前可设置已验证通知注册，各类通知投递仍在开发中。

## 获取方式

本仓库目前没有发布可直接安装的 iOS 构建，也没有提供 App Store/TestFlight 获取链接。下方流程适用于你从 ServerBee 运维方取得的构建，或自行从源码构建的应用。自行构建时先安装 Xcode 与 XcodeGen，然后执行：

```bash
cd apps/ios
xcodegen generate
open ServerBee.xcodeproj
```

从源码构建需要自己的 Apple Development Team。官方应用的设计由发布者运营的独立 Relay 保管 APNs 凭证，官方应用用户和自托管 Server 运维者无需持有发布者的密钥。本仓库尚未分发该签名应用，本地构建不能证明 App Attest 准入或 APNs 投递。

## 功能特性

- **二维码配对** -- 扫描 Web 应用中的二维码即可即时认证，无需手动输入 Token
- **已验证通知设置** -- 显式授权、订阅设置与 App Attest 设备验证，各类通知投递仍在开发中
- **实时指标** -- 通过 WebSocket 传输的实时服务器状态、CPU、内存、磁盘和网络指标
- **告警历史** -- 查看近期告警及其状态（触发/已解决）和详细信息
- **安全认证** -- 基于 Bearer Token 的认证，支持自动刷新（15 分钟访问令牌，30 天刷新令牌）

## 系统要求

- iOS 17.0 或更高版本
- 启用移动认证的 ServerBee 服务器实例（v0.8.0+）
- 已验证通知设置需要：配置 HTTPS Push Relay，并使用正确签名、支持 App Attest 的实体设备

## 设备配对

### 1. 启用移动认证（服务端）

在 v0.8.0+ 中，移动认证默认启用。除非需要调整令牌有效期，否则无需额外配置。

可选配置（`server.toml`）：

```toml
[mobile]
access_ttl = 900      # 访问令牌有效期（秒），默认 15 分钟
refresh_ttl = 2592000 # 刷新令牌有效期（秒），默认 30 天
```

### 2. 从 Web 应用开始配对

1. 登录你的 ServerBee Web 应用
2. 进入 **设置** → **移动设备**
3. 点击 **配对新设备**
4. 显示一个 5 分钟有效期的二维码

### 3. 使用 iOS 应用扫描

1. 打开 ServerBee iOS 应用
2. 在欢迎屏幕点击 **扫描二维码**
3. 将相机对准 Web 应用中显示的二维码
4. 应用将自动认证并显示你的服务器列表

## 管理已配对设备

### 查看已配对设备

在 Web 应用中，进入 **设置** → **移动设备** 查看所有已配对的 iOS 设备：

- 设备名称（如 "iPhone 15 Pro"）
- 配对日期和时间
- 最后活跃时间戳

### 撤销访问权限

要移除设备的访问权限：

1. 在 **移动设备** 列表中找到要移除的设备
2. 点击 **撤销** 按钮
3. 确认操作

该设备将立即登出，其所有令牌将被作废。

## 已验证通知设置

登录不会申请通知权限。打开 **设置 → 通知**，选择订阅后点击 **启用通知**。Server 确认保存的偏好后，iOS 才申请权限。安全通知仅限管理员，成功任务通知需单独选择。

通知页面使用 Server 确认的权限，即使本地缓存的登录角色已经过期。管理员被降权后，保存订阅或关闭通知会清除不再允许的安全类别。保存失败不会替换已确认的偏好。

回到应用、网络重连或注册恢复后，订阅保存失败仍会显示。页面保留尚未确认的选择，直到保存成功，或 Server 在更新的设置版本中确认已提交的合法偏好。仅注册成功不能确认这些选择。

页面分别显示系统权限与 Server 注册状态。保存失败会保留上次确认的偏好并显示错误。**重试通知设置**可重试验证，**打开系统通知设置**可调整 iOS 权限。App Attest 不受支持或被拒绝时，推送不可用，但监控与登录继续可用。应用会在启动、回到前台和网络恢复时核对注册，不会因登录而弹出权限请求。

**设置已确认不代表各类通知投递可用。** 使用**发送测试通知**仅测试当前认证安装。Server 加密消息，Relay 使用已验证的设备授权发送，Notification Service Extension 解密并本地化内容。页面分别报告服务商接受和设备展示，展示需在真机观察。点击有效测试通知会打开当前账户，旧账户、旧部署或无效消息不能触发导航。管理员安全规则通知已可用；告警和任务通知仍属于后续独立实现阶段。

测试通知先进入 Server 的持久加密队列。**等待发送**表示已在本地排队；**可重试**表示尚未确认提供商接受，将再次尝试；**已接受**表示收到 APNs 提供商回执；**永久失败**停止重试；**已过期**表示通知已到达创建后 30 分钟的期限。重试和 Server 重启不会延长期限。页面会刷新当前测试状态，响应丢失后重试会保留同一测试标识。网络结果不明确时可能重复发送，接受或重试均不保证只展示一次。

每次发送前，Server 都会检查账户、当前角色、移动会话、订阅、grant 到期时间和注册版本。关闭通知、退出登录、撤销设备或账户、会话过期、替换注册会阻止后续符合条件的发送。已在发送中或已被 APNs 接受的通知无法撤回。队列保存加密内容，不会另存明文通知历史。终态会清除密文，不含凭证的发送回执会保留，以避免重复入队重新开始有效期。

### 安全规则通知

管理员可以启用 **安全规则匹配**，并保存 Server 确认的订阅。成员不能订阅。原始检测本身不会触发移动通知，必须通过已启用的 SSH 新 IP 登录、暴力破解或端口扫描规则。阈值、用户名/CIDR 排除、Server 范围、维护窗口和现有的滑动去重窗口继续生效。即使多条规则匹配，同一事件也只为每个符合条件的安装生成一个逻辑安全通知，无需通知组。外部渠道继续使用各自配置的通知组。

Server 先保存原始安全事件和恢复标记，再将规则冷却与持久化的接收方意图一并提交，最后在同一事务中为所有符合条件的安装加密入队。队列写入失败会保留原始历史、浏览器更新、防火墙动作和外部通知，不会产生部分设备入队；故障解除或 Server 重启后会自动重试原始意图。意图固定接收方所有者、会话和注册版本，入队前再次核验，替换注册不能继承旧意图。安全通知在事件记录后 30 分钟过期。每次尝试前，Server 都重新检查当前管理员角色、安全订阅和移动会话。降权或修改订阅会停止后续排队投递。多个设备分别判断资格。模糊网络失败后的重试仍可能造成设备重复显示。

Notification Service Extension 会本地化匹配的事件类型。点击后，应用验证部署/账号、当前管理员角色及资源身份，再打开对应的 Server 安全事件列表和事件详情。已删除、不可用或无权限的目标显示可返回的提示；旧账号或部署的通知不能导航。本地测试不能证明真实 App Attest 验证，也不能证明 APNs 在前台、后台或应用终止状态下的投递。

### 隐私边界

Server 负责账户、会话授权和接收者选择。Relay 可见 APNs 令牌、来源 IP、时间、请求大小、环境、授权标识及加密内容，不应收到内容密钥或明文通知。申请权限前会向用户显示此说明。

Server 注册状态会核对 Relay grant。即使保存的到期时间尚未到达，已撤销或无法核对的授权也不会显示为已确认。Relay 续期成功但 Server 保存失败时，应用会在 Keychain 保留待确认的 grant，并在回到前台或重启后重试确认。App Attest key 仅属于一次配对登录，替换登录使用独立 key。

### Server 与 Relay 配置

通过 `[push_relay].url` 或 `SERVERBEE_PUSH_RELAY__URL` 指定独立 HTTPS Relay。无需通知组或旧 APNs 渠道。验证迁移会移除本账户的旧令牌，并持久隔离此安装与账户，关闭或注销现代通知后也不会恢复旧直连 APNs 群发。其他安装保留旧渠道。现有外部渠道继续使用自己的配置。

Relay 运维需要 Bun、OpenSSL 3 和持久化 SQLite。使用 `APP_ATTEST_ROOT_CA` 与 `APP_ATTEST_ROOT_SHA256` 固定 App Attest 信任根，`APP_ATTEST_APP_ID` 指定应用身份，`APP_ATTEST_BUNDLE_VERSIONS` 列出允许的 `CFBundleVersion`，`APNS_ENVIRONMENTS=sandbox,production` 可在同一 Relay URL 和数据库接纳开发与分发设备。单一环境部署仍可使用 `APNS_ENVIRONMENT`。`RELAY_DATABASE` 与 `RELAY_PORT` 指定状态文件与本地监听端口。Relay 仅绑定 loopback，需配置 TLS 反向代理与准入限制，challenge 和断言计数在重启后保留。没有公开发送端点或跳过验证的路径。

APNs 传输使用发布者专用签名输入 `APNS_TEAM_ID`、`APNS_KEY_ID`、`APNS_PRIVATE_KEY` 和 `APNS_TOPIC`。`APNS_PRIVATE_KEY` 是私有 PEM 文件路径，`APNS_TOPIC` 是应用 bundle 标识。这些凭证不得进入应用、Server 或仓库。隔离配置、签名检查与真机验收见仓库 `apps/push-relay/README.md`。测试不得指向 Heeler 的 Relay。

## 安全考量

- **令牌轮换**：每次使用时轮换刷新令牌（一次性使用），已消费的刷新令牌不能认证 API 或再次刷新。保留的哈希只能撤销原会话，使分阶段升级或轮换响应丢失后的清理仍可完成
- **固定过期**：访问令牌固定 15 分钟过期（无滑动续期），以限制被盗后的暴露时间
- **安全存储**：令牌使用适当的可访问性级别存储在 iOS Keychain 中
- **会话过期**：过期的访问令牌会话每小时清理一次。该任务不会删除配对设备的刷新会话：设备列表会在刷新会话过期后将其隐藏；刷新令牌轮换会保留原会话身份和安装注册；登出或撤销会删除会话及其保留的撤销证明哈希。

## 故障排除

### 二维码无法扫描

- 确保二维码在屏幕上清晰显示
- 检查二维码是否已过期（5 分钟超时）
- 尝试从 Web 应用生成新的二维码

### 通知设置失败

- 检查 Relay 地址及其 HTTPS 信任链。
- 在设置 → 通知中查看权限、验证与保存错误。
- 确认配对设备未被撤销，会话未过期。
- App Attest 需要受支持的实体设备及匹配的签名能力，模拟器通过不代表设备验证成功。
- 注册内容密钥前应配置最终的 HTTPS Server 地址。Server 请求拒绝重定向，设置失败后可在配置的地址重试。
- 核对应用私有凭据组及应用与扩展共享内容密钥组的签名。解密失败时仅显示通用文字。
- 各类通知投递尚未可用，可使用当前安装的测试通知操作。

### 认证失败

- 如果应用显示"会话已过期"，将自动刷新令牌
- 如果刷新失败，需要使用新的二维码重新配对
- 检查服务器时间是否正确同步（NTP）

## 技术细节

### 认证流程

1. **登录/二维码配对**：POST `/api/mobile/auth/login` 或二维码配对端点 → 返回 access_token + refresh_token
2. **API 请求**：在请求头中包含 `Authorization: Bearer {access_token}`
3. **令牌刷新**：收到 401 时，POST `/api/mobile/auth/refresh` 携带 refresh_token → 新的令牌对
4. **登出**：POST `/api/mobile/auth/logout` 作废该设备的所有令牌

### WebSocket 连接

iOS 应用维护 WebSocket 连接以获取实时更新：
- 连接 URL：`wss://your-server/api/ws/servers`
- 握手期间通过 `Authorization: Bearer` 头进行认证
- 自动重连，使用指数退避策略
- 访问令牌过期时连接自动关闭（重连触发刷新）
