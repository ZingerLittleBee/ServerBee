投递路径为 **Server → 独立 ServerBee Push Relay → APNs → iOS Notification Service Extension**。Server 负责订阅、授权、加密待投递消息和任务最终汇总，发布者的 Relay 负责 Apple 准入和 APNs 凭证。用户设置参见[移动端](/zh/docs/mobile)，Server 配置参见[配置说明](/zh/docs/configuration)。

本手册描述在明确授权的隔离环境中由运维者执行的操作，不会部署基础设施、安装密钥、发布代码或修改 Apple 账户。本仓库没有提供官方签名应用下载。本地夹具和 Simulator 测试不能证明真正的 App Attest 或 APNs 投递。

## 准备隔离环境

1. 记录 Server、Agent、Relay 和应用的精确版本、应用构建号、设备与 iOS 版本、UTC 时间及目标环境。使用独立 Server 账户、测试服务器和数据库、Relay 地址与状态、物理设备，与 Heeler 和生产服务隔离。告警、安全事件和命令输出使用无敏感内容的测试数据。
2. 发布者提供具有 APNs、App Attest 和共享 Keychain entitlement 的正确签名应用、对应 provisioning profile，以及已授权的 Relay 运维者。官方应用用户和自托管 Server 运维者无需持有发布者密钥或个人 Apple 开发者账户。从源码构建的维护者需要适用的签名身份。
3. 在已授权的 Relay 主机上使用 Bun 和 OpenSSL 3 安装锁定依赖。遵循仓库 `packageManager` 声明的版本，目前为 Bun 1.3.4；文档预览与检查使用 Node 24。文档 CI 的 Bun 安装步骤没有显式锁定版本。
4. 准备私有持久 SQLite 目录与 HTTPS 反向代理。Relay 可执行程序仅监听 loopback。代理限制请求体为 32 KiB，并配置来源 IP 限流、有界并发及连接和时间限制。在代理端配置可信对端链，Relay 忽略调用方提供的转发头。允许出站 APNs HTTP/2，保持时钟同步。

### 配置归属

| 归属 | 必需变量与用途 |
| --- | --- |
| Server | `SERVERBEE_PUSH_RELAY__URL` 或 `[push_relay].url`，最终 HTTPS Relay 地址；应用也使用无重定向的最终 HTTPS Server 地址 |
| Relay 信任 | `APP_ATTEST_ROOT_CA`，审核后的 Apple 根证书 PEM 路径；`APP_ATTEST_ROOT_SHA256`，独立核验的指纹；`APP_ATTEST_APP_ID`，App ID 前缀和应用 bundle 标识；`APP_ATTEST_BUNDLE_VERSIONS`，允许的签名构建版本 |
| Relay APNs | `APNS_TEAM_ID`、`APNS_KEY_ID`、`APNS_PRIVATE_KEY`（私有 PEM **路径**）、`APNS_TOPIC`（应用 bundle 标识，不是扩展标识） |
| Relay 状态 | `RELAY_DATABASE`，私有持久 SQLite 路径；`RELAY_PORT`，loopback 监听端口 |
| Relay 环境 | `APNS_ENVIRONMENTS=sandbox,production` 支持共存；也可使用 `APNS_ENVIRONMENT` 限定单一环境。复数配置优先。 |

配置值和密钥文件保存在仓库之外、运维者保护的运行环境中。Apple 密钥仅属于 Relay。不要记录 bearer grant、attestation、receipt、请求体、明文内容或内容密钥。重启必须保留 SQLite 状态，包括 challenge 消费记录、assertion 计数器和 grant 撤销记录。使用一致的 SQLite 备份，恢复旧准入状态可能回退重放保护，重新开放准入前需要运维者决定恢复策略。

通过独立可信审核固定 Apple 根证书，不能信任传入证明提供的根证书或通用 TLS 信任库。夹具 CA 仅传给测试构造器，生产可执行程序没有不支持设备的绕过入口或公共发送路径。使用 `bun --filter @serverbee/push-relay start` 启动已配置的隔离进程，再从签名设备验证设置。监听端口可达不代表设备准入成功。

### 检查签名应用

| 签名构建 | APNs entitlement / API 环境 | App Attest 环境 |
| --- | --- | --- |
| 开发构建 | `development` / `sandbox` | `development` |
| 分发、TestFlight 或 App Store 构建 | `production` / `production` | `production` |

检查签名应用和内嵌 `NotificationService.appex` 的实际 entitlement，不能从项目设置推断。针对已有构建，`codesign -d --entitlements :- "$SIGNED_APP"` 和 `codesign -d --entitlements :- "$SIGNED_EXTENSION"` 是只读检查。两个 target 的实际 Keychain access group 均需匹配 `$(AppIdentifierPrefix)com.serverbee.mobile.push` 和 plist 中的 `PushKeychainAccessGroup`。应用在私有组中保存认证凭证，扩展仅能读取内容密钥。确认 provisioning profile、App ID 前缀、bundle 标识、应用 `CFBundleVersion`、Relay 允许列表与 APNs topic 一致。签名或导出配置变更后重新检查实际 entitlement。

明确配置后，同一 Relay 地址和数据库可接收两种环境。每个 challenge、key、grant 和 APNs 请求保留自身环境。开发 key 不能更新或撤销分发 grant。仅验证开发环境时使用独立 sandbox Relay 和状态，不要将夹具指向生产 Relay 或借用 Heeler 凭证。

## 配置并启用通知

1. 配置 Server 的最终 HTTPS Relay 地址，启动已配置的 Server 并配对隔离设备。仅登录不应弹出通知权限请求。
2. 启用前阅读**设置 → 通知**中的隐私说明。Relay 可看到 APNs token、来源 IP、时间、请求大小、环境、grant 标识和密文，无法取得内容密钥或读取明文服务器名称、IP、告警文字、任务汇总和命令。
3. 选择**告警触发与恢复**。当前管理员还可选择**安全规则匹配**、**任务最终失败**，并单独启用默认关闭的**成功的任务运行**。保存明确订阅意愿、授予系统权限，再等待 Server 确认注册。无需通知组，保存失败时保留原先确认的选项和可见错误。
4. 使用**发送测试通知**，仅发给当前安装。记录状态和事件标识，再独立观察手机。**已接受**表示 APNs 提供商回执；**等待发送**表示本地入队；**可重试**表示已安排下一次尝试；**永久失败**停止重试；**已过期**表示到达原始事件时间加 30 分钟的期限。重启和重试不延长期限，结果不明的网络请求可能导致重复展示。
5. 从系统设置返回或恢复连接后，无需重新登录即可同步设置。普通认证刷新保留注册；退出登录、凭证或设备撤销、过期、权限丢失、取消订阅和替换注册会阻止后续符合条件的尝试。已在发送或被 APNs 接受的请求无法撤回。

扩展解密并本地化有界的认证内容，失败时显示不含目标的通用文字。重启后首次解锁前 Keychain 不可访问，可能触发此回退。前台使用系统横幅，WebSocket 仅更新应用状态。点击等待认证和当前密钥，核验部署、账户、安装及登录身份，再请求当前有权限的详情。已展示的真实通知超过 30 分钟投递期限后仍可点击；资源删除或失去权限时显示可关闭的回退页面。通知不会自动切换账户。

## 按观察层排障

| 现象 | 检查与恢复 |
| --- | --- |
| 登录时没有系统提示 | 符合预期，在通知页明确启用。曾拒绝权限时打开系统设置并返回应用，重复同步不能授予权限。 |
| 订阅保存失败 | 保留可见错误和确认选项，检查 Server 当前角色与设置版本，重试允许的选项。注册成功本身不确认失败的订阅保存。 |
| App Attest 不可用或被拒绝 | 检查受支持物理设备、实际签名、应用身份、根证书指纹、环境、版本允许列表、时钟和真实证明。临时错误可重试，登录与监控保持可用，不能绕过验证。 |
| 已保存 grant 显示未确认 | 检查 Relay HTTPS 连通性及 grant inspection。已撤销 grant 不会因保存的有效期仍在未来而有效。应用将待确认的新 grant 保存在 Keychain，再尝试 Server 确认。 |
| 测试等待发送或可重试 | 检查 Server 队列和 Relay 连接，不要导出负载。在原始 30 分钟期限内恢复，不要仅为重试结果不明的测试响应而创建新事件标识。 |
| 提供商或配置永久错误 | 通过不含秘密的原因和状态检查 topic、环境、授权及负载大小。HTTP 400 或 `BadDeviceToken` 环境歧义不能删除有效替换注册。APNs 410 `Unregistered` 仅对仍匹配发送版本的设备属于终止条件。 |
| 已接受但没有横幅 | 分别观察系统权限、专注模式、连接与应用状态。提供商接受不保证展示，Simulator 或夹具不能证明投递。 |
| 通用通知文字 | 检查共享签名 Keychain 组、首次解锁、当前内容密钥、完整性、协议版本和原始期限。不能转发明文或使用不可信回退字段导航。 |
| 某类别保持静默 | 检查该安装的确认订阅、当前角色与会话、规则覆盖范围、维护和抑制、原始期限。安全通知需要规则准入，任务通知需要最终完成及发起者或创建者归属，成功通知需要单独启用。 |
| 点击不可用或被拒绝 | 确认当前部署、账户、登录和 Server 授权。告警周期、安全事件或任务运行被删除时安全回退。投递过期本身不能拒绝已展示的真实目标。 |
| 重复展示 | 检查旧 APNs 迁移排除和前台单一系统横幅。提供商重试结果不明仍可能重复展示，不保证恰好一次；其他外部通知渠道保留配置行为。 |

## 自动化证据与交接

仓库 `tests/manual/mobile-push-integration.md` 列出组合 HTTP 和持久化场景及精确本地检查命令，`tests/manual/mobile-push-test.md` 提供 Server → 实际 Relay → 扩展的夹具贯通流程。记录执行、通过、失败和跳过数量、进程退出状态、候选完整 SHA、测试名称、日志及 `.xcresult` 路径。零测试检查或跳过的贯通测试不提供行为证据。专用 Simulator 仅用于本地边界检查，不能替代上表真实设备记录。通过正式生成器检查 API 零漂移，不能手改生成契约。修复集成失败时保留生产准入和密码学检查。
